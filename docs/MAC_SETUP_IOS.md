# Building the KHOJ iPhone app on a Mac

Instructions for a person or an AI coding agent working on a Mac. The Android app and all protocol work were done on Windows, where nothing iOS could be compiled. This file is the hand-over.

## 1. What exists and what does not

| Item | State |
|---|---|
| Android app (`app/`, `core/`) | Built and unit-tested (106 core tests pass). Field tests on phones are partly done. |
| Wire protocol for other platforms | Written: [GATT_BEARER.md](GATT_BEARER.md). iOS constraints: [CROSS_PLATFORM_RESEARCH.md](CROSS_PLATFORM_RESEARCH.md). |
| Test vectors | [interop/khoj_test_vectors.json](interop/khoj_test_vectors.json), generated by `core/src/test/.../InteropVectorsTest.kt` and checked by an independent Python implementation. **These bytes are the source of truth.** |
| Swift package `ios/KhojMesh` | Written but **never compiled**. Crypto, packet codec, GATT framing, a CoreBluetooth central and an optional peripheral. Expect compile errors. |
| iPhone app | **Does not exist yet.** That is the job. |

## 2. The job, in order

### Step 1: make the Swift package compile and pass the vectors
```bash
cd ios/KhojMesh
swift build
swift test
```
- Fix compile errors in `Sources/` and `Tests/` until `swift test` passes on macOS.
- `VectorTests` must reproduce `khoj_test_vectors.json` exactly: key derivation, decrypting the beacon, encoding it byte for byte, the public SOS frame, and reassembling GATT fragments.
- **Never edit the vectors or the Kotlin to make Swift pass.** If Swift disagrees with the vectors, Swift is wrong. The likely suspects (from the author's own notes) are `AES.GCM.SealedBox` with `ArraySlice` arguments, the `HKDF` call, `Bundle.module` resource lookup, and CoreBluetooth delegate signatures.
- Commit when green.

### Step 2: create the app
- New Xcode project `ios/KhojApp` (SwiftUI, iOS 16+), adding `ios/KhojMesh` as a local package.
- `Info.plist`: `NSBluetoothAlwaysUsageDescription`, `NSLocationWhenInUseUsageDescription`, `UIBackgroundModes` = `bluetooth-central`, `bluetooth-peripheral`, `audio` (for the siren).
- Implement the small router that the package leaves out ([GATT_BEARER.md](GATT_BEARER.md) section 8): duplicate cache keyed by (originId, packetId), TTL decrement, relay delay, never re-encrypt, SOS repeats until acknowledged, ACK for a received crew SOS or RALLY. Copy the behaviour of `core/src/main/kotlin/app/linkfill/core/mesh/MeshRouter.kt`.
- A backgrounded iPhone acts as a **low-power member**: set header flag `0x01` on everything it transmits, do not relay. Android phones that hear it act as its "friend" and re-send what it missed.

### Step 3: the minimum feature set (match Android)
1. **Join a group:** type the 16-character crew code, or scan the family QR (`KHOJ-CREW1:<code>`).
2. **Beacon:** send my position every 3 s (every 15 s in the background) as a crew BEACON.
3. **Members list:** name, distance and compass direction from their beacons; "last seen" age.
4. **SOS:** hold the red button for 2 s. Then play a loud siren, vibrate, and send a crew SOS plus a public SOS with my position. With no GPS fix, send lat/lon 0,0 ("position unknown"), then re-send once a fix arrives. Add a STOP SIREN button.
5. **Alerts:** an incoming SOS shows a full-screen alert and vibrates. A member farther than the group circle (default 50 m, after subtracting both GPS accuracies, back inside below 80%) or silent for 45 s raises "left the group circle" / "lost contact". The rule is `core/src/main/kotlin/app/linkfill/core/find/Circle.kt`.
6. Optional later: wristband "found" reports, helper role, Find Member. Not needed for the first version.

### Step 4: test against real Android phones
- Build the Android app on the Mac too (Android Studio, JDK 17): `./gradlew :core:test :app:assembleDebug`, then `adb install -r app/build/outputs/apk/debug/app-debug.apk`.
- On Android: create a group, show the family QR. On the iPhone: join with that code.
- Expect a log line on Android `GATT link up (server)` (`adb logcat -s KHOJ`). The iPhone should list the Android member, and SOS should cross in both directions.
- Then background the iPhone app and check it still reconnects (state restoration) and still receives SOS.
- Write the results (what worked, MTU seen, delays) into a new section of [GATT_BEARER.md](GATT_BEARER.md), section 10.

## 3. Rules
- **Do not change the wire protocol** unless it is truly needed. If you must, change the Kotlin first, run `./gradlew :core:test` (which regenerates the vectors), update [GATT_BEARER.md](GATT_BEARER.md), and keep Android and iOS in step. Old and new builds cannot talk to each other.
- The iPhone always **connects out** (central) to Android "door" advertisements: service `6b686f6a-0002-4b48-8f4a-6c696e6b6669`. A backgrounded iPhone cannot be discovered, so it must not rely on Android connecting to it.
- Plan for MTU 185 and at most 3 links per iPhone.
- Never put real keys in the repo. The police authority private key lives only in `secrets/`, which is git-ignored.
- Work on a branch (`ios-app`), commit in small steps, and say honestly in docs what was tested on a real iPhone and what was not.
